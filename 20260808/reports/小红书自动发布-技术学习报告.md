# 小红书自动发布 · 技术学习报告

> 报告日期：2026-08-06
> 目的：为 SellerAI 跨境工具推广小红书笔记自动发布，攻克「找不到发布按钮」卡点
> 现状：CDP 连接真实 Edge(9222) ✅、tiptap/ProseMirror 填标题正文 ✅、上传配图 ✅；卡在发布触发 —— 页面用自定义 Web Component `<XHS-PUBLISH-BTN>`（无 shadowRoot 空壳），右下角红色按钮显示「定时发布」（定时开关被误开），常规 DOM 枚举/文字/颜色搜索均失败

---

## 〇、核心结论（TL;DR）

1. **发布按钮 100% 可点，方案已验证**：小红书新版发布按钮就是 `<xhs-publish-btn>` 自定义组件，**不在 shadow DOM 里，按钮状态通过 host 元素属性暴露**。两个成熟开源项目（Go 版 xiaohongshu-mcp 9.7k stars、Python 版 autoclaw-cc/xiaohongshu-skills 1.7k stars）均成功点击它发布。
2. **推荐改法（两选一，首选 A）**：
   - **方案 A（推荐）：JS dispatchEvent 触发 `publish` 自定义事件**，不依赖坐标、不依赖 shadow DOM、不触发反爬鼠标指纹检测。前置检查 `is-publish="true"` 和 `submit-disabled` 属性。
   - **方案 B：真实鼠标点击组件坐标**（通过 CDP Input.dispatchMouseEvent 或 getBoundingClientRect 取中心点），需先关闭误开的定时开关。
3. **「定时发布」问题的根因**：右下角按钮文案由 `.post-time-wrapper .d-switch`（定时开关）控制——开关打开时按钮变「定时发布」。我们 v10 脚本疑似误点了这个开关。**先关闭它**（再点一次 `.post-time-wrapper .d-switch`，或确认其 aria-checked 状态），按钮就会恢复为「发布」。
4. **无可靠直接 API 发布方案**：edith.xiaohongshu.com 的 API 全部带 `x-s`/`x-t` 签名（逆向门槛高、易失效），公开的发布接口均为付费第三方服务（需手动点链接填草稿箱），不可用于生产。**浏览器自动化是当前唯一可靠路线**。
5. **有现成的半官方通道**：`xiaohongshu-mcp`（Go + go-rod 浏览器自动化，MCP/HTTP 双协议）可直接部署调用；`autoclaw-cc/xiaohongshu-skills`（Python + CDP，与我们架构完全相同）源码已 clone 到本地可直接借鉴。

### 1.1 xiaohongshu-mcp（xpzouying，Go + go-rod，9.7k★）⭐ 最权威

- 仓库：https://github.com/xpzouying/xiaohongshu-mcp
- 发布实现：`xiaohongshu/publish.go`（837 行）
- 技术栈：go-rod（相当于 Go 版 Playwright/Puppeteer），非 CDP 直连但原理一致

**发布按钮定位逻辑**（`findPublishButton`，2026-05 修复了"小红书页面更新后发布按钮定位失败"问题）：

```go
// 新版：xhs-publish-btn 自定义组件（优先）
widgets := page.Elements("xhs-publish-btn")
for _, widget := range widgets {
    if !isElementVisible(widget) { continue }
    isPublish := widget.Attribute("is-publish")      // "false" → 跳过（不是发布按钮，是暂存等其他按钮）
    if isPublish != nil && *isPublish == "false" { continue }
    submitDisabled := widget.Attribute("submit-disabled")  // "true" → 按钮禁用
    if submitDisabled != nil && *submitDisabled == "true" { return "新版发布按钮不可点击" }
    return &publishButton{elem: widget, isWidget: true}    // 找到了！
}

// 旧版回退：.publish-page-publish-btn button.bg-red
oldButtons := page.Elements(".publish-page-publish-btn button.bg-red")
// 检查 disabled 属性 / aria-disabled="true" / class 含 disabled
```

**点击方式**：新版组件走 `clickPublishWidget` —— `ScrollIntoView()` 后取 `Shape()`（元素四角坐标），取矩形**右 65%、垂直居中**的点（避开组件内其他元素），用 `humanize.ClickAt` 发真实鼠标事件。不是 JS click，是模拟真鼠标（带人类行为模拟，降低反爬嫌疑）。

**发布成功判定**（`waitPublishSuccess`）：点击后轮询页面 URL，**15 秒内 URL 不再包含 `/publish/publish` 即成功**（发布成功会自动跳转离开发布页）。这个判定逻辑直接可用。

**其他可借鉴点**：
- TAB 点击：`div.creator-tab` 遍历，用 `isElementVisible` + `elementFromPoint` 检测是否被浮层遮挡；被遮挡时按 Esc → 点空白 → **移除节点** 三级降级。
- 定时发布开关：`.post-time-wrapper .d-switch`（点击切换开/关）。
- 正文输入框候选选择器：`div[role="textbox"][contenteditable="true"]` → `div.tiptap[contenteditable="true"]` → `div.ql-editor` → placeholder 兜底。

### 1.2 autoclaw-cc/xiaohongshu-skills（Python + 原生 CDP，1.7k★）⭐ 与我们的架构完全一致

- 仓库：https://github.com/autoclaw-cc/xiaohongshu-skills

**发布按钮触发**（`click_publish_button`）——**最优雅的方案，直接命中我们的卡点**：

```python
# 1) 先注入 4 层响应捕获（XHR hook + fetch hook + console hook + DOM toast 观察器）
#    —— 目的是捕获发布接口的真实返回，识别业务错误码（-9136 = 账号风控）

# 2) 核心：dispatchEvent 触发 publish 自定义事件，绕开 shadow DOM 和坐标点击
fire_result = page.evaluate("""
    (() => {
        const host = document.querySelector('xhs-publish-btn[is-publish="true"]');
        if (!host) return 'not_found';
        if (host.getAttribute('submit-disabled') === 'true') return 'disabled';
        host.dispatchEvent(new CustomEvent('publish', {bubbles: true, cancelable: true}));
        return 'fired';
    })()
""")
```

**关键原理解析**：
- `<xhs-publish-btn>` 是 Vue 自定义组件，**虽然是自定义标签但不在 shadow DOM 内**（我们的"空壳"观察其实漏了：事件监听器挂在 host 元素上，Vue 通过自定义事件 `publish` 通信）。
- 直接 `dispatchEvent(new CustomEvent('publish'))` 即可触发 Vue 内部绑定的发布逻辑 —— **不依赖坐标、不依赖 shadow DOM、不会被反爬的鼠标事件指纹检测**。
- 这就是为什么"文字搜索/颜色搜索/坐标点击"全失败的答案：**按钮的真实触发入口是 host 元素上的自定义事件，不是内部 DOM**。
- 组件属性语义：`is-publish="true"` 标识这是发布按钮（页面上有多个 xhs-publish-btn，如"暂存离开"）；`submit-disabled="true"` 表示表单校验未过、按钮禁用。

**发布结果识别**：轮询 `window.__xhsPublishResult`（4 层捕获写入），15 秒超时；`code==0` 或 `success==true` → 成功；`-913x` 段或"违反/禁止发笔记/违规"关键词 → `AccountRiskControlError`（风控）。

**选择器清单**（`scripts/xhs/selectors.py`，与我们的页面同版本）：

```python

CONTENT_EDITOR = "div.ql-editor"
UPLOAD_INPUT = ".upload-input"

IMAGE_PREVIEW = ".img-preview-area .pr"
```

**发布 TAB 反爬细节**（`_click_publish_tab`，非常值得学）：
- 创作中心每个 TAB 渲染 3 份：①屏外诱饵（`left:-9999px` 无事件绑定）②带 `data-hp-kind`/`button-hp-installed` 的蜜罐（点了被标机器人）③**真 TAB 带 `data-hp-bound="1"` 标记**（反爬框架"已绑定真实事件"的标记）。
- 正确策略：选 `data-hp-bound="1"` 且无 hp 陷阱属性、且在视口内的 tab 点击，用 active class 切换确认。

## 二、直接调用发布 API 的方案（结论：不可行/不可靠）

### 2.1 官方 web 接口（edith.xiaohongshu.com）

- 阅读/互动类接口（feed、收藏、点赞、评论列表等）公开存在，社区有整理：`https://edith.xiaohongshu.com/api/sns/web/v1/feed` 等。
- **但发布类接口（上传图片、创建笔记）全部需要 `x-s`/`x-t` 签名头**，签名算法在 web 端混淆 JS 里（社区卖签名服务，如"获取小红书x-s/x-t纯js，加v"），逆向门槛高、易失效、有法律风险。
- **结论：不做。** 浏览器自动化（带真实登录态的 CDP）完全绕开签名问题。

### 2.2 第三方付费发布 API（不推荐）

- `xhslink.vip/api/xhs/publish`：POST 生成一个 `publishUrl`，**用户点链接后自动填充草稿箱，仍需人工确认发布** —— 不是真正自动发布，且是第三方商业服务（API Key 收费、配额制），账号安全无保障。
- `szlessthan.com` 等"小红书 API 对接平台"：同样需要申请 appId/appSecret，授权方式为链接授权/扫码，本质是第三方代理，不适合我们自研。

### 2.3 官方/半官方通道盘点

| 通道 | 类型 | 发布能力 | 可用性 |
|---|---|---|---|
| `creator.xiaohongshu.com/publish/publish` 网页 | 官方 | ✅ 图文/视频/长文/定时 | 我们正在用 |
| **xiaohongshu-mcp**（xpzouying） | 半官方开源 | ✅ 图文/视频/评论/互动（浏览器自动化） | ⭐ 成熟，9.7k★，可 Docker/二进制部署，MCP+HTTP 双协议 |
| **xiaohongshu-skills**（autoclaw-cc） | 开源 | ✅ 图文/视频/长文/定时/草稿 | ⭐ 与我们的 CDP 架构完全一致，MIT |
| **x-mcp**（xpzouying 的 Chrome 扩展版） | 开源 | ✅ 同上 | 浏览器扩展方案，零配置 |
| 小红书开放平台（企业号 API） | 官方 | ⚠️ 营销/推广类接口，需企业认证 | 不适合个人笔记发布 |
| TurboPush | 第三方 | ⚠️ 内容分发推送服务 | 需评估，非小红书官方 |

## 三、下一步修改建议（具体可执行）

### 立即修改（核心：发布触发 + 定时开关）

**① 发布触发改为 dispatchEvent（推荐，改动最小）**

在现有 publish 脚本中，把"找发布按钮"逻辑替换为：

```js
// 注入发布结果捕获（可选但推荐，用于识别风控）
// ...（参考 autoclaw 四层捕获，见本地源码 publish.py）

// 触发发布
(() => {
    const host = document.querySelector('xhs-publish-btn[is-publish="true"]');
    if (!host) return 'not_found';
    if (host.getAttribute('submit-disabled') === 'true') return 'disabled';
    host.dispatchEvent(new CustomEvent('publish', {bubbles: true, cancelable: true}));
    return 'fired';
})()
```

- `not_found` → 再兜底查 `xhs-publish-btn` 全部实例，打印 `outerHTML`/属性诊断；再兜底旧版 `.publish-page-publish-btn button.bg-red`。
- `disabled` → 说明表单校验没过（标题/正文/图片缺一），先自查表单。
- `fired` → 轮询 `window.__xhsPublishResult`（15s），`code==0` 或 URL 跳离 `/publish/publish` 判定成功；`-913x` 或违规关键词 → 风控，停手。

**② 先关闭误开的定时开关（解决「定时发布」文案问题）**

```js
// 如果右下角按钮文案是「定时发布」，说明定时开关开着：
const sw = document.querySelector('.post-time-wrapper .d-switch');
// 检查开关状态（aria-checked 或 class），若开启则点击关闭：
if (sw && (sw.getAttribute('aria-checked') === 'true' || sw.className.includes('checked'))) {
    sw.click();  // 关闭定时 → 按钮恢复「发布」
}
```

或者更稳：诊断时枚举 `.post-time-wrapper` 内 DOM，确认开关真实选择器后写死。**验证点：右下角红色按钮文案恢复为「发布」再触发**。

**③ 发布成功判定（三选一，建议组合）**

- URL 跳离 `/publish/publish`（15s 内）
- 页面出现"发布成功" toast
- 捕获到发布接口响应 `code==0`

### 后续增强（学到的反爬对抗经验）

**④ 发布 TAB 点击用 `data-hp-bound="1"` 过滤**（参考 autoclaw `_click_publish_tab`）：枚举 `div.creator-tab` 时跳过带 `data-hp-kind`/`button-hp-installed` 的蜜罐元素，只要视口内 + `data-hp-bound` 的真实 tab，用 active class 确认切换。

**⑤ 上传图片逐张等待预览计数**：`input[type="file"]` 上传后轮询 `.img-preview-area .pr` 数量达到预期再传下一张（60s 超时），避免多图上传漏图。

**⑥ 风控识别**：发布前检查 `submit-disabled`；发布后捕获响应 `-913x` 段（-9136=账号风控）或 toast 关键词"违反/违规/禁止发笔记"→ 立即停止并告警。频率控制：README 建议每天 50 篇上限，避免短时间大量操作。

**⑦ 状态诊断兜底**：找不到发布按钮时，执行诊断脚本打印所有 `xhs-publish-btn` 实例的属性（is-publish/submit-disabled/outerHTML 前 300 字符）+ 页面 URL，落盘截图，便于下次迭代。

## 四、风险提示

- 自动化发笔记违反小红书用户协议，有风控/封号风险。建议用测试小号、控制频率（≤50 篇/天）、实名认证后再批量。
- 选择器随前端迭代会失效，需要保留诊断+截图兜底机制。
- dispatchEvent 属于"模拟事件"，XHS 的反爬框架（data-hp-*）主要针对坐标点击陷阱；若后续 dispatchEvent 也被检测，可退化到方案 B（真实鼠标点击组件坐标，参考 xiaohongshu-mcp 的 clickPublishWidget）。
