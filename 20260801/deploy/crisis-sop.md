# 🚨 SellerAI 危机应对 SOP（Crisis Response SOP）

> 版本：V1.0 ｜ 创建于：2026-07-16
> 覆盖四类高频危机：**DeepSeek 余额耗尽 / API 限流 / Vercel 宕机 / 差评爆发**
> 原则：先止血 → 再通报 → 后复盘。涉及钱/决策的操作必须 [创始人] 亲手做。

---

## 🔴 场景一：DeepSeek 余额耗尽

**触发**：每日 09:00 余额检查 < ¥5，或用户反馈「生成失败 / API 报错」激增。

**标准应对步骤**
1. [AI] 确认：登录 DeepSeek 平台核对余额，确认非 Key 失效（先查 `.env` 中 API Key 是否正确）。
2. [AI] 止血：在官网/状态页置「临时维护中」公告，避免更多用户踩雷。
3. [AI] 通报：立即 @创始人 推送「🔴 DeepSeek 余额耗尽，需充值 ¥XX」。
4. [创始人] 充值：登录 DeepSeek 充值（建议预留 ≥ ¥50，单次成本仅 ¥0.006/次，足够数千次调用）。
5. [AI] 验证：充值后跑一次测试生成，确认恢复。
6. [AI] 撤公告 + 复盘：记录到 `reports/crisis-log-YYYY-MM.md`，评估是否调整自动充值阈值（建议余额 < ¥20 即预警）。

**预防**：将预警阈值从 ¥5 提到 ¥20；可研究自动充值（如平台支持）。

## 🟠 场景二：API 限流（429 / Rate Limit）

**触发**：每日 API 监控 429 报错 > 5 次，或用户集中反馈「请求过慢 / 偶发失败」。

**标准应对步骤**
1. [AI] 确认：统计 429 频率与时段，判断是否突发流量（如某帖爆了）还是代码重试风暴。
2. [AI] 止血（短期）：
   - 在前端加「请求过多，请稍候重试」友好提示；
   - 后端加指数退避（exponential backoff）+ 请求队列，避免重试放大限流。
3. [AI] 缓解（中期）：
   - 评估升级 DeepSeek 套餐 / 提升 QPS 额度；
   - 引入简单缓存：相同产品描述命中缓存，减少重复调用。
4. [创始人] 决策：是否临时限流免费用户、或加预算扩容。
5. [AI] 复盘：记录限流峰值、影响用户数、恢复时长。

## 🔴 场景三：Vercel 宕机 / 网站不可达

**触发**：每小时 Ping 监测不可达 > 5min，或用户反馈「打不开网站」。

**标准应对步骤**
1. [AI] 确认：访问 Vercel 状态页（status.vercel.com）确认是平台级故障还是本项目问题。
2. [AI] 自愈：[AI] 尝试自动重启 / 重新部署（redeploy）当前生产分支。
3. [AI] 通报：
   - 平台级故障 → @创始人「Vercel 平台故障，等待官方恢复，预计 XX」；
   - 项目级 → 拉取 Vercel 构建日志，定位报错。
4. [创始人] 兜底（如长时间未恢复）：评估临时切换备用域名/静态页，或引导用户走 Gumroad 结账直链 `xucan.gumroad.com/l/sellerai?wanted=true`（支付不受影响）。
5. [AI] 恢复后：验证端到端（生成 + 支付），撤公告，记 `crisis-log`。

**注意**：Gumroad 支付链路独立，宕机期间销售仍可发生，无需停售。

## 🟡 场景四：差评爆发

**触发**：单日新增 ⭐≤2 差评 ≥ 3 条，或 Reddit/FB 出现集中负面帖。

**标准应对步骤**
1. [AI] 分类：区分「真实 bug 反馈」vs「白嫖被拒退款恼羞成怒」vs「竞品黑稿」。
2. [AI] 真实问题 → 公开 + 私信回复：「感谢反馈，已定位，X 小时内修复并通知你」，并走 bug 修复流程。
3. [AI] 白嫖/无理差评 → 不纠缠，仅礼貌回应一次，截图留证（参照《运营分工协议》退款规则「有辱骂/威胁语气 → 拒绝 + 截图留证」）。
4. [AI] 疑似竞品黑稿 → 记录账号特征，不公开对线，转 [创始人] 判断是否举报。
5. [创始人] 决策：是否发澄清声明、是否对受影响用户补偿（如延长会员）。
6. [AI] 复盘：记 `crisis-log`，将高频差评点纳入周报 TOP 5 抱怨，推动产品迭代。

**红线**：绝不删评、绝不回骂、绝不泄露用户隐私。
