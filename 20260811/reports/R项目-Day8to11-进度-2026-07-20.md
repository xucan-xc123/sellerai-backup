## Day 9: 用户注册系统 ✅

### 新增文件
| 文件 | 说明 |
|------|------|
| `lib/auth/jwt.ts` | HMAC-SHA256 JWT (signToken / verifyToken) |
| `migrations/0006_users.sql` | users 表 (email 唯一) |
| `app/api/auth/send-code/route.ts` | 发送6位邮箱验证码 (Resend) |
| `app/api/auth/verify/route.ts` | 验证码校验 → 返回 JWT token + 创建 user_quotas |
| `app/api/auth/me/route.ts` (更新) | 支持 JWT Bearer 验证 (兼容原有 token hash 方式) |

### JWT 实现
- 使用 Web Crypto API (`crypto.subtle`) 的 HMAC-SHA256
- 密钥: `process.env.JWT_SECRET` 或 fallback `reviewiq-jwt-secret-2026`
- Token 有效期: 24小时
- 负载: `{ sub, email, plan, iat, exp }`

## Day 10: 前端集成 — 登录Modal + 配额显示 ✅

### 修改文件
| 文件 | 变更 |
|------|------|
| `app/tools/analyze/page.tsx` | 添加登录Modal (邮箱→验证码→JWT)，未登录显示"Sign in to analyze"按钮，已登录显示用户邮箱+计划标签 |

### 登录流程
1. 用户点击 "Sign in to analyze"
2. 弹出 Modal，输入邮箱 → 发送验证码 (Resend)
3. 输入6位验证码 → 验证通过 → 返回 JWT token
4. Token 存入 localStorage (`reviewiq_token`)
5. 页面刷新后自动检测 token 并获取用户信息

### 改进
- 登录后 analyze API 调用自动附带 `Authorization: Bearer` header
- 显示用户邮箱和计划标签 (Trial)

## ⚠️ 注意事项

1. **JWT 密钥**: 当前使用 fallback `reviewiq-jwt-secret-2026`，建议在 wrangler.jsonc 中设置 `JWT_SECRET` 环境变量
2. **GUMROAD_WEBHOOK_SECRET**: 需在 Cloudflare Dashboard 环境变量中配置，否则 webhook 将拒绝所有请求
3. **WSL 窗告**: 构建环境为 Windows，OpenNext 建议使用 WSL 以获得最佳性能
4. **旧版 SellerAI 代码**: `lib/quota.ts` 仍为 SellerAI 的原有配额系统 (visitor_id-based)，与新的 user_quotas 并⾏。后续可整合
