# SellerAI 成本核算补充 — BYOK（用户自带API Key）场景

> 补充日期：2026-07-18
> 背景：创始人指出原账本只算"所有生成走我们DeepSeek key（¥0.006/次）"，**漏算用户自带API（BYOK）场景**。本文补齐。

## 为什么要算 BYOK
1. 原账本假设所有套餐都烧我们的DeepSeek余额 → 用户越多我们成本越高，规模不经济
2. BYOK 模式下：用户填自己的 DeepSeek/OpenAI key，生成请求直接打用户key，**我们边际成本≈0**
3. 这同时解决两个问题：
   - ④成本核算漏洞（现在补齐）
   - ①生存点：BYOK档可"无限生成"且我们不烧钱，形成差异化（竞品大多只卖自家额度）

## 修订后套餐成本模型（含BYOK）

| 套餐 | 生成走谁 | 单用户月生成成本 | 我们承担 |
|------|---------|----------------|---------|
| Free Trial（7天） | 我们的key | ¥0.006×限5次≈¥0.03 | 我们 |
| Starter $19.9 | 我们的key（月度限额） | ¥0.006×100次≈¥0.60 | 我们 |
| Growth $24.9 | 我们的key（月度限额） | ¥0.006×300次≈¥1.80 | 我们 |
| **Pro $39.9 / BYOK** | **用户自己的key** | **¥0** | **¥0** |

## BYOK 档利润重算（$39.9/月，Gumroad）
| 项目 | 金额 |
|------|------|
| 客单价 | $39.9 |
| 支付手续费（Gumroad 10%+$0.30） | -$4.29 |
| 到账收入 | $35.61 |
| 生成成本（BYOK，用户自担） | **$0** |
| 域名摊销 | -$1.0 |
| Cloudflare | $0 |
| **单人月净利润** | **≈ $34.6** |
| **毛利率** | **≈ 87%**（且规模经济：用户越多成本不增） |

## 切 Creem 后 BYOK 档
- 手续费 3.9%+$0.40 = $1.96 → 到账 $37.94
- 单人月净利 ≈ $36.9，**毛利率 ≈ 92%**，规模零边际成本

## 结论修正
- 原结论"1个付费用户即盈利"依然成立，但**BYOK档让毛利从83%升到87-92%且规模不烧钱**
- 定价策略建议：把 BYOK 作为 Pro 档核心卖点（"无限生成，用你自己的API key，我们分文不收"），既差异化又锁利润
- 必须补进成本账本：Starter/Growth 的"月度生成限额"要真实落地（否则用户超量就烧我们的钱，原账本假设崩塌）——这依赖 s-auth-loop 正在做的配额中间件
