## 🔴 [P0] 问题

### P0-1: Gumroad Webhook 签名验证缺省时静默跳过

- **位置**: `app/api/gumroad-webhook/route.ts:72-76`
- **描述**: 当环境变量 `GUMROAD_WEBHOOK_SECRET` 未设置时，webhook 仅输出 `console.warn` 后直接处理请求，没有任何签名验证。攻击者可以伪造 Gumroad 事件（包括 sale/refund/cancellation）来操纵用户订阅状态。
- **影响**: ❗ 如果 prod 环境未正确配置该环境变量，攻击者可以免费激活任意邮箱的 Pro 订阅，或恶意撤销付费用户资格。
- **建议修复**:
  1. 在 Cloudflare Dashboard 强制配置 `GUMROAD_WEBHOOK_SECRET`
  2. 在代码中将缺失 secret 的情况改为 HTTP 500（拒绝请求）而非静默放行
  3. 增加 deployment check / CI 验证环境变量是否就绪

### P0-2: FAQ 显示每月 3 次免费，代码实际执行每日 3 次

- **位置**: `components/FAQ.tsx:91` vs `lib/quota.ts:11`
- **描述**: FAQ 写的是 "The Free plan includes 3 AI-generated listings per month"，但 `lib/quota.ts` 的 `FREE_DAILY_LIMIT = 3` 以及 `checkQuota()` 中的日限额逻辑实际执行的是 **每天 3 次**。Blog 帖文中也多次提到 "3 free listings per day" 与 FAQ 自相矛盾。
- **影响**: ❗ 用户会看到 FAQ 说每月 3 次，但实际使用了 3 次后当天就无法继续，造成极度困惑和信任危机。这是对用户的直接误导。
- **建议修复**: 统一文案为"每天 3 次免费生成"。FAQ 修改为 "daily free tier includes 3 AI-generated listings"。

### P0-3: Auth Token 以明文存储在数据库中

- **位置**: `app/api/auth/verify-code/route.ts:114-119`
- **描述**: `auth_tokens` 表存储的是原始 token 字符串（"sai_xxx"），未做任何 hash（如 SHA-256）。如果 D1 数据库被攻破，所有活跃会话的 token 将被直接暴露。
- **影响**: ❗ 所有登录用户的会话可被劫持。且该 token 存储于前端 `localStorage`，XSS 也能窃取。
- **建议修复**:
  1. 存储 `SHA256(token)` 而非原始 token
  2. 验证时对传入 token 做同样的 hash 再查表
  3. 后续可迁移到 httpOnly Secure cookie

## 🟡 [P1] 问题

### P1-1: `dangerouslySetInnerHTML` 使用用戶生成内容（间接）

- **位置**: `components/ListingGenerator.tsx:442`
- **描述**: `dangerouslySetInnerHTML={{ __html: genDescHtml }}` 渲染 DeepSeek API 返回的 HTML 描述。虽来源是 AI 模型而非直接用户输入，但模型可能被 prompt injection 诱导输出恶意 HTML/JS。
- **影响**: 存在 XSS 媒介风险，尤其是当攻击者可操纵 product notes 输入。
- **建议修复**: 使用 DOMPurify 或其他 sanitizer 过滤 HTML，或使用 React 组件替代 `dangerouslySetInnerHTML`。

### P1-2: 价格信息多处不一致

- **位置**: `components/Pricing.tsx` (实际 $19.9) vs `lib/blog.ts` blog 帖文 (提到 "$29/mo")
- **描述**: Blog 多篇文章（如 multi-platform-listing-differences 篇）提及 "Pricing starts at $0...$29/mo for the core plan"，但 Pricing 组件实际显示 $19.9/mo（Starter/Monthly）和 Annual $199/yr。Blog 内容与产品定价严重不一致。
- **影响**: 用户看到 blog 后可能认为贵了，或认为价格不透明。
- **建议修复**: 全局搜索 blog.ts 中所有 $29 字符串并更正为 $19.9，保持产品信息一致。

### P1-3: 配额检查 fail open（避险方向错误）

- **位置**: `app/api/generate-listing/route.ts:117-120`
- **描述**: 当 `checkQuota()` 抛出异常时，`checkAuthorization()` catch 块返回 `{ authorized: true }`（允许通过）。这意味着 D1 数据库临时故障时，所有请求（包括未付费用户）将无限制通过。
- **影响**: 风险相对可控（故障窗口有限），但政策上是安全风险的逆向选择。
- **建议修复**: 将 fail open 改为 fail closed（拒绝请求 + 503），或至少在 quota 服务不可用时切换到保守限额。

### P1-4: Gumroad webhook 取消事件处理逻辑异常

- **位置**: `app/api/gumroad-webhook/route.ts:158-162`
- **描述**: 取消事件中代码执行 `UPDATE licenses SET status='active'`（将 license 状态设为'active'）—— 但 license 原本就是 'active'，这是无操作。预期应该保持 license 可用但标记用户为 `cancelled`。当前逻辑虽无意中正确（license 保留），但语义不清晰。
- **影响**: 低 — 功能上正确，但代码表现与语义不一致。更严重的是，UPDATE users 时 `WHERE subscription_status='active'` 条件可能因为用户之前的状态不是 'active'（如 'trial'）而无法更新。
- **建议修复**: 将 licenses 的 SET 改为仅对已撤销的恢复，或删除多余的 UPDATE。同时放宽 users 更新条件以覆盖更多场景。

### P1-5: Gumroad webhook 退款事件使用 `UPDATE licenses WHERE email = ?` 影响所有同名邮箱

- **位置**: `app/api/gumroad-webhook/route.ts:167`
- **描述**: 退款/争议事件用 `UPDATE licenses SET status='revoked' WHERE email = ?`，如果同一个邮箱买过多次，所有 license 都会被撤销。同样的，users 表也是根据 email 全部过期。
- **影响**: 同邮箱的多笔订单中，只退款一个订单会导致该邮箱下所有有效 license 被撤销。
- **建议修复**: 应使用 `gumroad_sale_id` 精确匹配到单一 license。

### P1-6: CORS 配置过度宽松 — 回显 Origin

- **位置**: `app/api/quota-status/route.ts`, `app/api/activate-license/route.ts`, `app/api/generate-listing/route.ts`
- **描述**: 多个 API 路由使用 `Access-Control-Allow-Origin: origin || "*"`，回显请求中的 Origin。这允许任何第三方网站通过浏览器 API 读取用户的配额状态。
- **影响**: 低 — 无敏感个人数据泄露，但可能被滥用进行用户枚举或跨站数据采集。generate-listing 路由有 Origin 白名单逻辑（evaluateOrigin），但 quota-status 和 activate-license 没有。
- **建议修复**: 统一使用 Origin 白名单机制，拒绝未授权来源。

### P1-7: API 速率限制仅基于内存，不跨 Worker 实例

- **位置**: `app/api/auth/verify-code/route.ts:18`（`verifyRateMap`）和 `app/api/generate-listing/route.ts`（`rateLimitMap`）
- **描述**: 速率极限制通过 `Map<string, RateEntry>` 在内存中实现。Cloudflare Workers 可能有多个实例同时运行，内存 state 不共享。攻击者可通过轮换 IP 绕开限制。
- **建议修复**: 使用 D1 或 KV 实现跨实例的速率限制，或用 `env.RATE_LIMIT` 绑定 Cloudflare Rate Limiting API。

### P1-8: Secrets 文件 `secrets/gumroad.txt` 被检入仓库

- **位置**: `E:\QClaw\Work-QClaw\sellerai-frontend\secrets\gumroad.txt`
- **描述**: Gumroad webhook secret 以明文写入 `secrets/gumroad.txt`。该文件是否提交到 git 取决于 `.gitignore` —— gitignore 中仅排除了 `wrangler.jsonc` 和 `.env*`，**未明确排除 `secrets/` 目录**。
- **影响**: ⚠️ 如果该文件被推送至远程仓库，Gumroad webhook secret 将完全暴露。
- **建议修复**: 1) 验证该文件是否在 git 跟踪中；2) 将 `secrets/` 加入 `.gitignore`；3) 将该 secret 移入 Cloudflare Dashboard 环境变量。

### P1-9: `next.config.ts` 和 `next.config.js` 同时存在且内容冗余

- **位置**: 项目根目录
- **描述**: 同时存在 `next.config.ts`（TypeScript，空配置）和 `next.config.js`（CommonJS，空配置）。两者内容完全一样，造成配置冗余和混淆。OpenNext 和 wrangler 会优先使用哪一个不可预测。
- **影响**: 构建结果可能不确定。
- **建议修复**: 删除 `next.config.js` 文件，只保留 `next.config.ts`。

### P1-10: LanguageSwitcher 组件已定义但未在 UI 中使用

- **位置**: `components/LanguageSwitcher.tsx` — 项目中无任何页面引用
- **描述**: i18n 框架完整（`lib/i18n.ts` + `lib/i18n-context.tsx` + `components/LanguageSwitcher.tsx`），但 `LanguageSwitcher` 组件从未被任何页面或 Navbar 引用。布局中 `I18nProvider` 已包裹，但用户无法切换语言。
- **影响**: 多语言支持框架存在但功能不可达。
- **建议修复**: 将 `LanguageSwitcher` 嵌入 Navbar，或移除无用代码。

### P1-11: Blog 帖文提到未实现的定价计划

- **位置**: `lib/blog.ts`（多篇帖文提到 "$29/mo for the core plan"、"Free plan includes 3 free listings per month"）
- **描述**: Blog 有几篇内容提到 "$29/mo" 定价和月度限额，但实际产品是 "$19.9/mo" 和日配额。文章信息落后于产品实际定价。
- **影响**: 品牌信任受损，SEO 出现矛盾信息。
- **建议修复**: 全局更新 blog.ts 中所有提到定价和配额的内容。

### P1-12: `sessionStorage.setItem("sellerai_open_tool", "1")` 设置了但从未读取

- **位置**: `app/tools/ToolsClient.tsx:20`
- **描述**: 代码设置 `sessionStorage.setItem("sellerai_open_tool", "1")` 后跳转到 "/"（首页），但没有任何组件读取这个 storage key。这是死代码或未完成的跨导航通信逻辑。
- **影响**: 无直接影响，但增加认知负担。
- **建议修复**: 实现读取逻辑，或移除这行死代码。

## 🟢 [P2] 问题

### P2-1: 首页布局缺少安全 HTTP 头

- **位置**: `next.config.ts` / `app/layout.tsx`
- **描述**: 没有配置 Content-Security-Policy、X-Content-Type-Options、X-Frame-Options、Strict-Transport-Security 等安全头。虽然 Cloudflare 边缘可以提供部分保护，但应用层应该设置。
- **建议修复**: 在 `next.config.ts` 中配置 `headers()` 函数，或通过 `middleware.ts` 添加安全头。

### P2-2: 没有 SEO 专用的 meta image / og:image

- **位置**: `app/layout.tsx:43`（OpenGraph 配置）
- **描述**: `openGraph` 配置了 `title` 和 `description` 和 `url`，但缺少 `images`（og:image）。社交媒体分享时没有预览图，影响 CTR。
- **建议修复**: 添加 `openGraph.images` 配置，指向项目 logo 或品牌图。

### P2-3: Blog 帖文 inline `dangerouslySetInnerHTML` 风险评估不足

- **位置**: `components/ListingGenerator.tsx:442`
- **描述**: 同 P1-1，但 P2 层级强调 20 秒超时（AbortSignal.timeout(20000)）可能不足以覆盖所有 DeepSeek 请求场景。
- **建议修复**: 将超时延长至 30s，并添加重试机制。

### P2-4: Console.log 在 Worker 生产环境输出

- **位置**: 多处（gumroad webhook, flywheel 日志, generate listing 等）
- **描述**: 项目中大量 `console.log` 和 `console.warn` 在生产代码中存活。Cloudflare Workers 的 console.log 调用会产生写日志的 I/O 消耗，且在免费 tier 每日日志量有上限。
- **建议修复**: 1) 对于 flywheel 日志，使用独立的 telemetry 端点非阻塞写入；2) 使用环境变量控制 debug 日志级别。

### P2-5: DeepSeek API Key 缺少轮换机制

- **位置**: `app/api/generate-listing/route.ts:75`
- **描述**: `DEEPSEEK_API_KEY` 是单一 API key。如果被泄露（如日志误打印），需要手动在 Cloudflare Dashboard 更换。
- **建议修复**: 规范 key 使用前缀以便识别泄露来源，考虑使用 Secrets Manager 定期轮换。

### P2-6: 免费用户 anonymous 模式可能被滥用

- **位置**: `lib/visitor.ts` + `lib/quota.ts`
- **描述**: `visitor_id` 是客户端生成的 UUID 存储在 localStorage。用户可以清除 localStorage 来重置配额（每天 3 次），或使用无痕/新浏览器无限刷新。
- **影响**: 对于免费产品的滥用风险，通常可接受。但如果需要收紧，应考虑 IP+UA fingerprint。
- **建议修复**: P2 级别 — 可忽略或后续添加 IP 辅助校验。

### P2-7: Blog 文章 part 结尾 callout 链接使用完整 URL（https://xucan.gumroad.com/l/kajyx）硬编码

- **位置**: `lib/blog.ts` 中多处
- **描述**: Gumroad 购买链接在多篇 blog 中硬编码。如果将来迁移到其他支付平台，更新成本高。
- **建议修复**: 抽取为常量 `GUMROAD_URL`（已在 Pricing.tsx 中），blog 也使用同一常量。

### P2-8: 没有 robots.txt 文件

- **位置**: 项目根目录
- **描述**: 虽然有了 `app/robots.ts` 导出，但导出方式和格式需确认是否正确生成 `/robots.txt`。查看代码后确认是标准 Next.js App Router 格式，可行。
- **建议修复**: （已达标）仅注明此项已检查通过。

## 额外观察（未够上问题级别）

- D1 查询全部使用参数化 prepared statement — 无 SQL 注入风险

- Auth code API 有蛮好的邮件频率限制（每个邮箱 60s）

### 📝 建议
- 建议添加 `middleware.ts` 统一管理 CORS 和安全头

- 考虑添加 Sentry 或其他 APM 监控 Worker 运行时错误
