### 4.3 Fail-Closed 原则

所有权限检查均实现 fail-closed:
- `product_access` 为 `null`/`undefined` → JSON.parse fallback 为 `["listing"]`
- 产品不在数组中 → 403
- DB 查询异常 → 403
- 未登录 → 401

## 六、已知风险 & 待办

### 🔴 高优先级
1. **Gumroad 商品 ID 未填入**: `PRODUCT_MAP` 中的 `listing-only-product-id`、`pro-product-id`、`max-product-id` 需替换为实际 Gumroad 商品 ID（在 Gumroad 后台创建三个商品后填入）
2. **旧用户默认权限**: 现有用户的 `product_access` 默认为 `["listing"]`，已付费但不含 `product_access` 的用户会失去 Pick/ReviewIQ 访问权限 → 需手动迁移或通过 webhook 重放
3. **reviewiq-db / pick-db 废弃**: 两个旧 D1 数据库仍在 Cloudflare 上存在，可保留过渡期后删除

### 🟡 中优先级
4. **reviewiq-frontend 的 JWT auth 用户**: 用 JWT 登录的用户，`user_quotas` 和 `users` 表可能没有对应 email，需要在代码中做 graceful fallback
5. **Webhook 兜底逻辑**: 当前兜底 `PRODUCT_MAP[productId] || ["listing","pick","reviewiq"]` 意味着未知 product_id 会全开权限，需确认这是有意为之

### 🟢 低优先级
6. **pick-frontend 和 reviewiq-frontend 的 migrations 目录**: 已不再需要各自的 migration 文件（现全部走 sellerai-db），可清理
