## 1.3 S 项目缺陷 → R 项目必须避免

| S 项目踩坑 | 代价 | R 项目补救方案 |
|:----------|:----:|:--------------|
| **Reddit 养号失败（新号直接发推广→被删/封）** | 浪费 3 天运营周期，账号权重受损 | R 项目不做 Reddit 推广。改为 ProductHunt 首发 + SEO 自然流量 + Twitter/X 冷启动，不走社区养号路线 |
| **浏览器操控走不通（CDP 会话冲突、3 agent 抢同一标签）** | 数小时调试，最终放弃 | R 项目推广策略全走 API（ProductHunt API / Twitter API），**不做任何浏览器自动化发帖** |
| **定价策略反复（$19.9 → $14.9 → $19.9/$199 来回改）** | 前端改 3 次，Gumroad 商品重做 2 次 | R 项目 **第一版定价即钉死**：$9.9/月 Free→Pro→Enterprise 三级，不改（数据驱动调价也至少等 100 付费用户后再动） |
| **前端组件反复增减（3 次重构：多组件→删除→再添加）** | 浪费约 2 天开发工时 | R 项目 **MVP 只做 Landing + 核心功能页 + 定价**，不做博客/多工具/国际化/主题切换。功能冻结期 2 周 |
| **部署路径问题（Vercel→Netlify→CF Workers 三换）** | 3 天部署困境，域名 DNS 反复改 | R 项目 **直接上 CF Workers**，首日即定。不试 Vercel/Netlify |
| **wrangler 配置问题（token 权限缺 SSL/Zone Edit→530）** | 多次 530/10000 错误 | 文档化：token 必须含 Workers Scripts=Edit + Zone SSL=Edit + Zone=Edit |
| **审批流程阻塞（团队商讨后才执行，周期长）** | 每步决策延迟 1-5 小时 | R 项目预设决策树：什么级别的事自己做，什么才找创始人 |
| **Gumroad webhook 历史上无签名验证** | 存在伪造 webhook 风险 | 已修复，R 项目可以直接用修复版 |
| **Token 明文存储在 auth_tokens 表** | 已用 SHA-256 修复（crypto.ts） | 直接复用修复版 |
| **无 trial 系统（用户注册后直接 free/paid 二选一）** | 转化率瓶颈 | R 项目 **第一版就带 trial**（3-7天无限试用），复用已有 0002_trial.sql |
| **推广策略混乱（什么都不行→全团队自转→Reddit→放弃）** | 2 天无效试错 | R 项目启动前写好推广方案，创始人拍板后执行。不做"边做边想" |
| **"创始人无受众"认识延迟（7/16 以为是群，7/17 才知没有）** | 方案方向错了 1 天 | R 项目首日先确认创始人现有流量池（很可能也没有），以此为起点设计获客 |
| **Codex 反复（7/18 晚上→7/19 早上→又停）** | 策略混乱 | R 项目不依赖外部付费模型，全部走 DeepSeek 或本地推理 |
| **成本控制的全局账本太晚（第 2 周才出完整成本核算）** | 早期决策缺乏数据支撑 | R 项目开工前出完成本模型 |
