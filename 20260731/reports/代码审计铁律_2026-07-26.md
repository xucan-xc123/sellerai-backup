# ⛔ 代码审计铁律 — 2026-07-26 23:17 生效（最高优先级）

## 背景

2026-07-26，创始人发现试用过期后用户回到每天3次免费（白嫖），以及登录用户绕过所有配额检查。此前团队已执行至少两次"全链路安全审计"，均报告"零问题"。这证明**现有审计流程不产生可验证结论**。

## 核心原则

> **不验证 = 没审计。审计不靠"看上去没问题"，靠"跑一遍全路径"。**

---

## 铁律 1：攻击场景清单（禁止通读式审计）

**废除**："从头到尾看一遍代码找bug"
**改为**：每次审计前，先列一张完整的**攻击/白嫖场景清单**，逐条验证。

### 最低场景清单（任何与配额/付费/权限相关的改动）

| 场景 # | 攻击方式 | 验证方法 | 预期结果 |
|:--|:--|:--|:--|
| A1 | 未注册用户用不同 visitor_id 刷 | 循环5次POST，换5个随机 visitor_id | 第4次 402 |
| A2 | 同一IP换 visitor_id 绕过IP限制 | 同一IP生成6个不同 visitor_id | 第6个被限 |
| B1 | 注册3天试用，3天后不付费继续用 | 手动设 trial_ends_at=昨天 → POST | **402**（不是200） |
| B2 | 试用过期后用同一邮箱重新注册 | 注册API → POST → 403 | 403 blocked |
| B3 | 试用过期后换邮箱重新注册同 visitor_id | 注册 + POST | 402 或 403 |
| C1 | 付费用户 cancelled/expired 仍可用 | 模拟 webhook cancelled → POST | 正常服务（grace period） |
| C2 | License 已 claim 被另一个 visitor 用 | 不同 visitor_id 激活同一 key | 400 "already in use" |
| D1 | 匿名用户每天额度用完跨天重置 | 用完+等跨天（或手动设 quota_date=昨天） | 第二天恢复3次 |
| D2 | Bearer Token 登录用户绕过 visitor_id 配额 | 登录后 POST（无 X-Visitor-Id） | 仍受配额限制 |
| E1 | Product Access 只买 KeyWordIQ 调用 Listing API | Bearer Token + product_access=["keywordiq"] → POST generate-listing | 403 "not included" |
| E2 | 直接调用 DeepSeek API bypass 应用层 | 无 X-Visitor-Id 调 POST | 401 "Authentication required" |

**规则**：这条清单是底线，不是上限。每次审计可以加场景，但不能减。

## 铁律 2：审计必须带线上证据

**禁止**在审计报告里出现以下字样：
- ❌ "看起来没问题"
- ❌ "逻辑上不存在漏洞"
- ❌ "代码检查通过"

**必须**每一条场景附带：
- ✅ 实际 HTTP 状态码
- ✅ response body 关键字段
- ✅ 验证时间戳

**示例（正确格式）：**
```
B1 试用过期测试：
  STEP 1: 手动设置 trial_ends_at = '2026-07-23'
  STEP 2: POST /api/generate-listing with X-Visitor-Id=test-b1
  RESULT: HTTP 402, {"error":"quota_exhausted","subscription_status":"expired"}
  ✅ PASS — 过期用户被拦截
```

## 铁律 3：每次审计不同 agent

**同一套代码禁止由同一 agent 执行两次审计。**

- 第一次审计：Agent A
- 第二次审计：Agent B（不许看 Agent A 的报告，从零开始）
- 对比两者的发现 → 找出被漏掉的

实现方式：`sessions_spawn` 两个独立子 agent，分别给同样的 prompt（"按审计铁律检查以下代码"），不给对方的结论。

---

## 铁律 4：改动上线后必跑冒烟测试

任何代码改动 `wrangler deploy` 上线后，**必须**至少执行：

1. `GET /` → 200
2. `GET /api/quota-status` → 200 + 正确状态
3. `POST /api/generate-listing` → 200（无 token 前提下用免费配额测试）
4. 新用户注册 → 200 + trial 状态正确
5. 额度耗尽后 → 402

以上5条有任何失败的，不许关闭任务。

## 自检唤醒

任何 agent 在审计任务中如果：
- 超过5轮还没开始逐条跑场景验证
- 在写"看起来没问题"

→ 立即自查是否违反了铁律1和2，退回重做。
