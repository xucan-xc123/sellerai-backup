## 二、关键发现 1：本编辑页根本没有订阅/会员控件

对编辑页做了**完整的 DOM / HTML 扫描**（主内容区 143KB HTML）+ 多次可访问性树快照 + 视觉核对，确认：

- 全页**只有 3 个 `<select>` 下拉**：
  1. Call to action（I want this! / Buy this / Pay）
  2. Currency（$/£/¥/… 19 种货币）
  3. **Refund period**（No refunds / 7-day / **14-day** / 30-day / 6-month）
- **不存在任何**以下控件：
  - 商品类型切换（Product ↔ Membership）
  - 计费周期（Monthly / Yearly / Weekly / Quarterly）
  - 免费试用天数（Free trial）
  - 多档位/多价格档（tiered pricing）
- 页面上唯一的 "subscription" / "$19.90/month" / "monthly" 字样，全部出现在**商品描述文案和 Fine print 文本里**——是卖家自己写的宣传文字，**不是**后台的订阅功能。
- 视觉可见的定价区只有一个 `Amount` 数字输入框 + 货币选择，即「一次性 $19.90」。

**这意味着：要把它变成「真订阅（$19.90/月 + $119/年 + 3天试用）」，在 `tpxppi` 这个一次性商品的编辑页里**做不到**。Gumroad 的会员/订阅是创建时选定的独立商品类型，不能事后从一次性商品「升级」。

### ✅ 给创始人的可行路径
- **方案 A（推荐）**：在 Gumroad 后台**新建一个 Membership（会员）类型商品**，在创建时选 Recurring，设 Monthly $19.90 + Yearly $119.00，并可开 3-day free trial；本商品 `tpxppi` 保留或下架。
- **方案 B**：若 Gumroad 在该账户支持「把现有一次性商品转会员」，需创始人在自己浏览器里走官方转换入口（编辑页里没有，可能需要从 Products 列表或创建流程触发，非本页）。

## 三、关键发现 2：Save 按钮本次会话未提交任何改动

我本来已成功用键盘把 **Refund period 选到 14-day**，但保存后刷新页面又变回 30-day。为排除「只是下拉没选对」，我做了**受控对照组测试**：

**对照组（改动金额，最不容易出错的字段）：**
1. 刷新页面 → Amount = `19.90`
2. 用真实键盘输入把 Amount 改成 `49.90` → 页面内值显示 `49.90` ✅
3. 点击 **Save changes** → 页面内值仍显示 `49.90` ✅
4. **刷新页面** → Amount **变回 `19.90`** ❌（原值）

- 同时在 Save 前后抓了 network HAR：**Save 期间产生了 0 条产品更新请求**（`requestCount: 0`）。
- 同理，Refund period 无论用程序 `select`、还是真实键盘 `ArrowUp`+`Enter`，选到 14 后 Save，刷新后一律回到 30-day。

**诊断**：该编辑页是 **Inertia.js（Laravel + React）单页应用**。通过自动化注入的字段值没有写进 React 的受控表单 state，所以表单始终处于「未修改（not dirty）」状态，Save 实际上把原始值又提交了一遍 → 服务器无变化 → 刷新即回原值。换句话说，**在这个调试会话里，Save 是空操作（no-op）**，连金额这种简单字段都存不进去。

> 注：这不是「订阅功能缺失」导致，而是**整个编辑页的保存机制在本自动化通道下不落库**。即便只改退款天数也存不住。
