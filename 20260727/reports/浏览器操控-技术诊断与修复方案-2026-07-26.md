## 二、根因诊断

### 问题 ①: CfT（内置 Chrome）启动崩溃 — **VC++ 并行配置错误**

**症状**:
```
Failed to launch Chrome at ...chrome.exe: 应用程序无法启动，因为应用程序的并行配置不正确。(os error 14001)
```

**根因**:
- agent-browser 自动下载的 `chrome-151.0.7922.34` 依赖更高版本的 **Microsoft Visual C++ 2022 Redistributable**
- 当前系统已安装的 VC++ 2022 版本是 **14.44.35211**，而 CfT chrome 151 需要更新的 14.4x 版本或特定的 CRT 清单。
- `chrome.exe` 文件只有 **4MB**（正常应有 100MB+），说明是 stub exe，真正的引擎在依赖的 DLL 中但 VC++ 加载失败。

### 问题 ②: Edge CDP 自动启动失败 — **xbrowser 自动启动逻辑有 bug**

**症状**:
```
Auto-launch failed: All CDP discovery methods failed for 127.0.0.1:9333
```

**根因**（通过手动测试验证）:
- ✅ **手动启动 Edge CDP 完全正常**:
  ```
  msedge.exe --remote-debugging-port=9222 ... → CDP HTTP 200, Browser: Edg/150.0.4078.83
  ```
- ❌ **xbrowser 的自动启动流程失败**——问题出在：
  1. xbrowser 自动扫描端口找 Edge (默认找 9334)
  2. 找不到后尝试自动启动 Edge → 但启动时添加了 `--headless` 参数
  3. Edge v150 的 headless 模式在 xbrowser 的 spawn 调用下异常退出/CDP 端口未及时就绪
  4. 自动启动后 10s 等待 CDP 超时 → 报错

### 问题 ③: 外网访问被 DNS 阻断

**症状**:
- Gumroad (app.gumroad.com) 直连超时
- OpenClaw 内建 browser tool 有 SSRF 防护，`69.63.190.26` 直接 IP 访问被拦截
- web_fetch 同样超时（DNS 被墙或代理未走）

### 问题 ④: Edge 多进程残留

**症状**:
```
tasklist | findstr msedge → 10+ 个进程残留在后台
```
- xbrowser 的 `stop --force` 只杀 Edge 主进程，`msedgewebview2.exe` 等子进程残留
- 进程残留占用 profile 目录的 SingletonLock → 下次启动失败

## 三、修复方案（优先级排序）

### 🔴 P0: 修复 Edge CDP 自动操控

**方案 A（推荐）— Edge CDP 预先启动脚本**
创建一个 PowerShell 启动脚本：
1. 强制清理所有 Edge 进程（包括 webview2）
2. 用新 profile 启动 Edge + `--remote-debugging-port=9222`
3. 等待 CDP 就绪
4. 然后 xbrowser 直接连 `127.0.0.1:9222`（而非自动启动）

**方案 B — CfT 重新安装/修复 VC++**
- 安装最新的 VC++ 2022 Redistributable (x64)
- 重新运行 `xb setup` 重新下载 CfT

**方案 C — 修改 xbrowser 启动参数**
- 将 `--headless` 改为 `--headless=new`（Edge v150 新 headless 模式）
- 增加等待超时从 10s 到 20s

### 🟡 P1: 外网访问代理配置

- 检查系统代理 127.0.0.1:7897（Clash 或其他）
- 配置 xbrowser shield allowlist 允许 `127.0.0.1:7897`
- 或直接关闭 shield（不推荐）

### 🟢 P2: 进程清理自动化

- 创建 `browser-cleanup.ps1` 一键清理脚本
- 集成到 xbrowser run 的前置步骤

## 四、立即执行（方案 A 实施）

```powershell
# Step 1: 强制清理所有 Edge 进程（包括 webview2）
taskkill /f /im msedge.exe 2>$null
taskkill /f /im msedgewebview2.exe 2>$null
Start-Sleep -Seconds 2

# Step 2: 使用新 profile 启动 Edge + CDP 端口 9222
$edgePath = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
$profileDir = "C:\Users\Administrator\.qclaw\tools\xbrowser\profiles\edge"
Start-Process -FilePath $edgePath -ArgumentList @(
    "--remote-debugging-port=9222",
    "--user-data-dir=$profileDir",
    "--no-first-run",
    "--no-default-browser-check",
    "--headless=new"   # Edge v150+ 新 headless 模式
) -WindowStyle Hidden

# Step 3: 等待 CDP 就绪（最多 15s）
$timeout = 15
$sw = [Diagnostics.Stopwatch]::StartNew()
while ($sw.Elapsed.TotalSeconds -lt $timeout) {
    try {
        $r = Invoke-WebRequest -Uri "http://127.0.0.1:9222/json/version" -UseBasicParsing -TimeoutSec 2
        if ($r.Content -match "Edg/") {
            Write-Host "✅ Edge CDP ready on port 9222"
            break
        }
    } catch {}
    Start-Sleep -Milliseconds 500
}

# Step 4: 配置 xbrowser 跳过 auto-launch，直接使用现有 CDP
# → 需要修改 xb.shield allowlist 允许 9222
```

## 六、反爬/防检测现状评估

团队使用的 agent-browser 0.25.3 内置以下反检测能力：
- ❌ **无指纹伪装**（WebGL/Canvas/WebRTC 指纹与原版浏览器一致）
- ✅ **无头模式可检测** — `--headless=new` 有一定混淆
- ❌ **无代理轮换**
- ❌ **无自动化标记隐藏** （`navigator.webdriver` 标记未处理）

对于被 Cloudflare 高强度保护的站点（ProductHunt、Medium、Quora 等），当前技术栈不够。但 Gumroad、Reddit、普通博客等不需要强反爬的站点完全够用。

**反爬增强建议（中期）:**
- 使用 real browser fingerprint：undetected-chromedriver 或 puppeteer-extra-stealth
- 添加代理轮换（BrightData/oxylabs）
- 操作间隔随机化（human-like delays）
