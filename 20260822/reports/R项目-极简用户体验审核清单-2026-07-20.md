# R项目 ReviewIQ — 用户操作极简体验审核清单

**日期**: 2026-07-20 | **审核人**: 参谋长 | **版本**: v1.0

---

## 核心理念

创始人明令：**站在用户操作极简思维去严格专业审核，避免漏斗BUG。**

ReviewIQ的用户只有一条路径：**打开→输入→出结果→分享/付费**。每一步有断点就流失。

---

## 1. 用户完整路径漏斗

```
用户访问 Landing Page（URL: reviewiq.xxx.com）
  ↓ —— 漏斗1: 访问→注册 ——
  看到产品介绍 → 点CTA "Start Analyzing" → 跳转到注册
  ↓ —— 漏斗2: 注册→登录 ——
  输入邮箱 → 收验证码 → 输入验证码 → 完成注册 → 自动登录
  ↓ —— 漏斗3: 登录→首次分析 ——
  进入工具页 → 看到输入框 → 输入ASIN → 点"开始分析"
  ↓ —— 漏斗4: 分析中→出报告 ——
  进度条运行 → 爬取评论 → AI分析 → 生成报告（渐进加载）
  ↓ —— 漏斗5: 看报告→再次使用 ——
  查看报告 → 分享/下载 → 点"再次分析"
  ↓ —— 漏斗6: 再次使用→付费 ——
  配额用完 → 提示升级 → 点链接 → Gumroad购买 → 自动激活（≤5秒）
```

## 9. 极简设计原则（落地方案）

| 原则 | 解释 | R项目落地方案 |
|:----|:----|:------------|
| **一步到位** | 所有操作≤2次点击 | 注册（1步：输邮箱+验证码×1页面）→分析（1步：输入ASIN+点按钮）→看报告（自动加载）3步走完 |
| **不思考** | 用户不需要想"下一步点哪" | CTA颜色=全站唯一高亮色；位置固定hero区正中央；文案含动词"Analyze Now" |
| **即时反馈** | 每个动作后≤0.5秒内给反馈 | 按钮disabled+spinner为0秒；进度分阶段提示；成功态绿勾；失败态红提示+重试；额度不足黄提示+升级链接 |
| **容错** | 用户犯错时友好提示 | 无效ASIN格式→即时红字提示+示例ASIN；超时→重试按钮+邮件客服；网络断开→"Check your internet connection" |
| **不打扰** | 非必要不弹窗 | 配额不足提醒内嵌报告底部；升级CTA不在分析中途弹；不做newsletter弹窗；不做cookie banner（不用第三方cookie） |
| **一致** | 全站体验统一 | 所有页面同一颜色体系（紫色主色调区分SellerAI蓝色）；同一按钮圆角/字号；同一间距体系（Tailwind class语义化） |
| **可逆** | 用户能回退 | 所有页面有←Back；浏览器返回不白屏；分析结果页有"Try another ASIN" |

## 10. 漏斗BUG排查 — S项目教训→R项目预防

| 漏斗位置 | S项目BUG | 具体表现 | R项目硬性预防 |
|:--------|:--------|:--------|:------------|
| **注册** | 验证码延迟/收不到 | Resend邮件有时30秒+才到，用户以为系统坏了 | ①Resend `sendEmail()`超时3秒触发重试②前端加"Resend code"按钮（60秒CD）③备用邮件模板（纯文本备用防止HTML渲染慢） |
| **登录** | 登录完跳回首页不是工具页 | `callbackUrl`未指定→React Router默认跳`/` | 全部auth API callbackUrl**硬编码**→`/app`，不读取URL参数 |
| **使用** | 匿名用户直接拦在门外 | 未登录用户进`/app`→弹出LoginModal→用户关闭 | 进`/app`后**不拦**，允许1次免费分析（visitor ID计数），结果页底部引导注册 |
| **付费** | Gumroad链接404 | `gumroad.com/l/sellerai` 实际是 `/l/kajyx` | ①硬编码Gumroad链接→代码里用常量`GUROAD_PRODUCT_URL`②构建后自动curl校验③上线前创始人手动点一遍 |
| **付费** | Webhook激活延迟 | 支付成功→30分钟后license才生效 | ①Webhook收到→**同步更新D1**（不异步）②前端分析接口每次带quota查询③提交流程结果页直接查最新quota |
| **部署** | 部署后某功能消失 | 某次wrangler deploy后FAQ组件不渲染 | 构建后跑自动化脚本：`curl /app` `curl /api/health` `curl /pricing` 全200才算部署成功 |
| **移动端** | LoginModal溢出 | 手机屏宽度<Modal宽度→左右被裁 | 移动端Modal `width: 100vw - 32px`；`max-height: 90vh` + overflow-y:auto |
| **移动端** | QuotaBadge遮挡 | 悬浮在右下角→挡住输入框/按钮 | Badge不悬浮！放在Navbar内或输入框上方一行小字 |
| **FAQ** | 文案与代码不一致 | FAQ→"per month" 代码→`DAILY_LIMIT = 3` | FAQ**不手写**文案，直接读取常量渲染：`{FREE_DAILY_LIMIT} per day` |
| **Gumroad** | 商品描述严重过期 | 线上Gumroad写的"仅Amazon/10次免费/30天退款/一次性购买"全错 | 上线前1天专人对Gumroad商品页逐字段核对 |
| **定价** | 定价卡与Gumroad价格不对齐 | Pricing.tsx→$19.9/月，Gumroad→一次性$19.90 | `lib/pricing.ts`常量→Pricing组件和Gumroad都用同一个源 |
| **文案** | 虚假承诺 | "1 listing = 1 sale" "Save $100+/month" | 禁止夸张文案。所有claim要有数据支撑或标注"estimated" |
| **Token** | 明文存储 | auth_tokens表直接存token → DB泄露全丢 | **必须SHA-256 hash后存库**（S项目已修复，R项目直接复用crypto.ts） |
| **Webhook** | 无签名验证 | 任何人POST /api/gumroad-webhook就能伪造支付事件 | **必有签名验证**（GUMROAD_WEBHOOK_SECRET缺失→直接500拒绝） |
| **Trial** | 无Trial系统 | 注册后只能free→用户粘性低 | MVP就带3天无限试用→到期回到免费额度（每日3次） |
| **CTAs** | 多CTA打架 | "Try Free" + "Start Generating"两个按钮 | 每页面只1个主CTA按钮 |
