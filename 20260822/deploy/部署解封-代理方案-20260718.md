# 🎉 SellerAI 部署链路解封（2026-07-18 11:15）

## 真凶（重大发现）
卡了好几天的"部署失败"**根本不是**权限/账号被封/token失效问题。
**真凶：wrangler / curl 连接 Cloudflare API 时没走代理，被网络阻断（连接超时/Authentication error假象）。**

之前所有"Vercel BLOCKED""Netlify 403""token 权限不足"的判断部分成立，但 Cloudflare Worker 这条路**一直是通的**，只是命令没挂代理连不上。

## ✅ 正确部署方法（固化，以后照做）

### 前置
- 代理地址：`http://127.0.0.1:7897`
- CF Token：已存于环境变量 `CLOUDFLARE_API_TOKEN`（53字符，active，2026-07-17 起生效）
- 工作目录：`E:\QClaw\Work-QClaw\sellerai-frontend`

### 部署三步（PowerShell）
```powershell
cd E:\QClaw\Work-QClaw\sellerai-frontend
$env:HTTP_PROXY="http://127.0.0.1:7897"
$env:HTTPS_PROXY="http://127.0.0.1:7897"

# 1) build
npx opennextjs-cloudflare build

# 2) deploy（关键：环境已带 HTTP(S)_PROXY）
npx wrangler deploy

# 3) 验收
curl -s -o NUL -w "HTTP %{http_code}\n" --max-time 20 -x http://127.0.0.1:7897 "https://sellerai.listaikit.com/"
```

### Token 验证（排查用）
```powershell
curl -s --max-time 25 -x http://127.0.0.1:7897 "https://api.cloudflare.com/client/v4/user/tokens/verify" -H "Authorization: Bearer $env:CLOUDFLARE_API_TOKEN"
# 返回 "This API Token is valid and active" 即正常
```
