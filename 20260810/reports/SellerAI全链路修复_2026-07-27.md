# SellerAI 全链路修复报告 2026-07-27

## 用户投诉
1. "所有用户必须注册登录了才能免费3天使用" — 之前可以绕过验证码直接注册
2. "输入邮箱验证码后报错没有反应" — verify-code 成功后前端卡住

## 根因分析

### 问题 1：双注册路径并存
- `/api/register`：不需要验证码，有邮箱+visitorId就能注册并拿3天试用
- `/api/auth/send-code` + `/api/auth/verify-code`：验证码流程
- 结果：任何人都能跳过验证码白嫖 3 天

### 问题 2：verify-code 响应不完整
- 后端返回：`{ok, token, trial_ends_at, email}` — **缺少 subscription_status 和 product_access**
- LoginModal 里：`saveAuth(token, {subscription_status: "free", ...})` — 硬写 "free"
- `/api/auth/me` 查不到正确的用户状态 → 后续调用失败
- 前端无可见错误提示 → 用户看到的就是"没反应"

### 问题 3：generate-listing 可匿名调用
- 无 Bearer token 时 fallback 到 X-Visitor-Id 匿名配额路径
- 任何 visitorId 都能调 API

## 修复清单（4 个文件）

### 1. `app/api/generate-listing/route.ts`
**改：** 删除匿名 X-Visitor-Id fallback 路径
**新逻辑：** 无 Bearer token → 直接 401 "Login required. Please log in to start your 3-day free trial."
**效果：** 所有 API 调用必须登录，杜绝白嫖

### 2. `app/api/register/route.ts`
**改：** 整个 POST handler 替换为 410 响应
**新逻辑：** 返回 "Please use the email verification flow: send-code then verify-code."
**效果：** 旧注册路径彻底封死

### 3. `app/api/auth/verify-code/route.ts`
**改：** 返回增加 subscription_status + product_access
**新字段：**
```json
{
  "ok": true,
  "token": "sai_...",
  "trial_ends_at": "2026-07-30",
  "email": "...",
  "subscription_status": "trial",
  "product_access": ["listing"]
}
```
**效果：** 前端能正确存储用户状态

### 4. `components/LoginModal.tsx`
**改：** saveAuth 使用 data.subscription_status（不再硬写 "free"）
```tsx
// 修复前
subscription_status: "free",
// 修复后
subscription_status: data.subscription_status || "trial",
```
**效果：** 登录后用户状态与实际数据库一致

### 5. `app/api/health/route.ts` (新建)
**功能：** 健康检查端点
**响应：** `{"status":"ok","version":"sellerai-v1","timestamp":...}`
